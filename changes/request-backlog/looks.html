2 · Research

  1. Drafts wait, one Submit sends them. A code-review tool keeps comments “pending”, seen and edited only by their author, until Submit review sends them together; the pending review can be discarded whole. Here: Q2’s drafts are this model; C copies it closely, A and B keep the count and Submit on every screen. A code-review tool’s docs
  2. New requests land in a triage inbox, outside the workflow. An issue tracker holds issues from outside the team in Triage, out of every other view, until someone accepts, declines, merges or snoozes; asking for more is a comment while it stays. Here: New requests in Waiting for you are that inbox: Discussing is “comment and keep”, Ready accept, Parked decline. A and B keep it a group of its own; C mixes it in. An issue tracker’s Triage docs
  3. A list to triage, a board to watch flow. A service-desk tracker shows the same items as a list, for “triaging and assigning new requests”, or a board, for work moving through a workflow; a code host’s boards are the values of one status field, moved by dragging. Here: In progress, To review and Done follow a change, not a hand, so three of a board’s columns refuse drops, and seven open requests give a board little flow to show. A service-desk tracker’s views · a code host’s board layout
  4. WCAG 2.2 · 2.5.7 Dragging Movements (AA). What a drag does must also work with a single pointer and no drag; the kanban example is selecting a card, then an arrow button or a pop-up menu of the columns. Keyboard support alone does not meet it. Here: every direction moves a request with a state menu; B’s drag is extra, never the only way. W3C, Understanding 2.5.7
  5. Move with a menu, return focus, announce it. A design system’s drag-and-drop guidance puts the moves in an action menu on each item, advises against custom arrow-key schemes, returns focus to the trigger after a move and announces the item’s old and new place in a live region. Here: the state menu returns focus to its button, and a status line says “Undo after closing a note: Discussing → Ready, unsent”. A design system’s drag-and-drop guidelines
  6. From a board, an item opens over the board and has its own address. A work tracker opens a card as a modal issue view over its board (a side panel is the other setting), and the board’s address carries the open issue, so a link reopens both; a card tool opens a card over its board from the card’s own link; a planner tool opened task details in a dialog covering the board, then added a side pane and remembers each person’s choice; a code host’s projects open an item in a side panel, with a deep link and a link to the full page; the brief’s issue tracker opens the full issue page, with a key for a quick peek. Here: with the side panel declined, the prevailing choice is the dialog; /backlog/<id> reopens the board with it open, and closing returns to where it was opened. A work tracker: modal or sidebar · its board address · a card tool’s card links · a planner tool’s dialog and side pane · a code host’s deep links · the issue tracker’s peek
  7. The text and its activity in a main column, details beside it. A work tracker puts description fields on the left, with Activity at the bottom of the issue, and context fields, status and details, “down the right side … (or at the bottom in a single-column layout)”; the brief’s issue tracker keeps properties in a sidebar beside the content; when a card tool moved comments beside the description, its users asked for the stacked view back. Here: D keeps notes under the request and puts state, who asked, features, changes and the file in the details column; narrow, it is one column, the state and details as a short block under the title, in the wide dialog’s order so focus follows reading. A work tracker’s field layout · its Activity section · a card tool’s comments beside
  8. WAI-ARIA APG, modal dialog. A dialog with aria-modal, named by its visible title: focus moves in on open (to the title, for structured content), Tab and Shift+Tab stay inside, Escape closes, and focus returns to what opened it. A work tracker’s own bug, focus not set onto its board’s modal, shows what breaks without it. Here: D’s dialog takes focus on its title, keeps it, closes on Escape and gives it back to the card; the board, top bar and tray behind are inert. W3C APG, modal dialog · a work tracker’s focus bug

3 · Four directions

They differ in where a request lives and how drafts show. D is the owner’s pick: B’s board, with a dialog in place of its side sheet. New in all three: the request state pill (a word and an icon per state), the draft mark (dashed outline and a word), notes, the note composer, the request form, the state menu, the clash box, and the token --edge-strong.

A · Third tab

Backlog is a tab beside Waiting for you and Explore; the list groups requests under state headings and a request opens in the detail pane. Drafts: “3 unsent · Submit” in the top bar. New: the drafts popover.

B · Board

Backlog is a full-width board; cards open in a side sheet and move by a menu, dragging optional. Draft cards and notes are dashed; a bottom tray counts them. New: board, card, side sheet, tray, review panel.

C · Conversation

A request is a thread; moves and the change’s progress are timeline lines; Waiting for you is one stream. Drafts are Pending, as in a code review. New: thread, timeline line, docked drafts panel.

D · Board with a request dialog owner’s pick

B’s board as drawn; a card opens a large dialog over the dimmed board: the request and its activity in a main column, state and links in a details column. It has its own address and is full-screen when narrow. New: request dialog, scrim.

8 · Recommended pick: D · Board with a request dialog owner’s choice, pending confirmation

The owner chose the board, and not its side sheet. D keeps B’s board as drawn, with its Move menus, toggles and tray, so people who are not developers meet the layout they know from task tools, and opens a request the way those tools open an item from a board: a large dialog over the dimmed board, with its own address, the request and its notes in a wide main column and the state, features and changes in a details column, as a work tracker’s issue view lays them out. That fixes B’s weakest point, reading a discussion in a narrow sheet, and the modal dialog pattern gives focus, Escape and the return to the card a known shape. D costs what B costs: a second layout beside the map’s list and detail, a board that is sparse at seven requests, three columns that follow a change and refuse drops, and while a request is open the board behind is out of reach. A stays the lighter fallback if the owner reconsiders.
